## Design

- **Arms:** `openai-agents 0.21.1` and `langgraph 1.2.11` (same-day control).
- **Model:** `gpt-4o`, temperature 0, `parallel_tool_calls: false`. One model, held constant.
  Keeps the result directly comparable to `/langgraph-vs-pydantic-ai-benchmark/`.
- **Task suite:** `methodology/real-pilot-task-suite-v0.1.0.json`, suite version 0.1.1,
  sha256 `ec72e744…f339bf` — **verified unchanged today** against the gpt4o pilot manifest.
  Frozen before warmup, four tasks: `inventory-reorder`, `dependent-shipping-quote`,
  `recover-stale-revision`, `refund-policy-minimal-tools`.
- **Runs:** **20 per subject per task** — 2 × 4 × 20 = **160 scored runs**, plus 8 warmup.

That run count is deliberate. The July pilot used 5 runs per cell; the benchmark protocol
requires a minimum of 20 for a completion rate reported with a confidence interval. bc-040 is
the first run at full suite compliance, and the control arm gets the same treatment, so the
comparison inside this benchmark is sound even though it cannot be laid over July's numbers.

**gpt-4o-mini is out.** It would add 160 runs for about $0.02, but it roughly doubles wall
time and server hours, and we already know mini fails `refund-policy-minimal-tools` on date
arithmetic — a known model limitation, not a framework finding.

## Stages

**Stage 1 — SERP brief (paid, ~$0.004).** One DataForSEO pull on `openai agents sdk`, live
SERP including AI Overview, teardown of the top-ranking pages. At KD 72 the brief decides
whether the review can rank at all or needs a long-tail entry point instead. Free work:
competitor teardown, keyword-map check for cannibalisation against `/agentic-ai-frameworks/`.

**Stage 2 — Static audit (free, local).** Full static audit of `openai-agents 0.21.1` and its
dependency closure before anything executes: credential access, network calls, filesystem
writes, process execution. Same treatment that accepted LangGraph 1.2.9 and rejected CrewAI
1.15.5. Verdict and lock SHAs to Neo before install.

**Stage 3 — Server (needs approval).** CX23 in `hel1`, or region-hunt if unavailable — never
a larger plan. Check `GET /datacenters` read-only first. Build two isolated, pip-less,
hash-verified environments, one per arm. Network blocked except the OpenAI endpoint,
telemetry off.

**Stage 4 — Adapter and smoke test (free of model spend).** Write
`adapters/worker_openai_agents.py` against the neutral adapter contract
(`methodology/real-pilot-adapter-contract-v0.1.0.md`) — a subject is a config row, not new
runner logic. Acceptance tests in fake mode, matching the 25/25 bar the existing two
adapters meet. Any install or runtime failure is itself a reportable DX finding.

**Stage 5 — Warmup then scored run (paid).** One clean single-pass warmup per arm; if it
needs more than one iteration the run is not publication-eligible and I stop and say so.
Then 160 scored runs, counterbalanced order, OOM-safe batching. Destroy the server the same
day and report what was destroyed.

**Stage 6 — Analysis and article.** Completion rate with confidence intervals, token cost
median and spread, latency median/p95, and the failure taxonomy — the taxonomy is the part
no competitor publishes. Overlapping intervals mean "no measurable difference", not a winner.
Raw JSONL published. Then draft, type-aware QA, publish, sitemap gate, internal linking.

## Risks

- **0.21.1 is one day old.** Mitigation above: pin back to 0.21.0 and disclose if it misbehaves.
- **The SDK is OpenAI's own.** Benchmarking OpenAI's framework on an OpenAI model invites a
  fairness objection. The control arm and the published raw data are the answer; the page
  should name the objection rather than wait for a reader to raise it.
- **KD 72.** The SERP brief may say the head term is not winnable yet. If so, the measurement
  is still worth having and the entry point changes — that is a Stage 1 decision, not a
  reason to skip the benchmark.
